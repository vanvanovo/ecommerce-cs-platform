## 四、设计要点

1. **A2A 与 MCP 的分工实例**：知识库检索封装成 **A2A 独立 Agent**（能力型依赖：独立部署、独立演进、AgentCard 能力发现），而订单/物流是 **MCP 工具**（数据型依赖）——"A2A 管 Agent 间、MCP 管工具调用"在本项目里有真实落地；
2. **Task 状态机**：`completed` → 读 artifacts；缺参数 → `input_required` 追问；异常 → `failed`（不炸服务）——标准 A2A 任务语义；
3. **检索后端可插拔**：mcp / inproc / http 三模式一份接口，**B 后补**（一期 ecommerce_rag 包成 `/search` HTTP 后零改动切换）；
4. **超时 + 降级闭环**：A2A 超时/失败 → 检索返回空 → QA 走 `llm_direct` 兜底（照实说不确定、建议转人工）——**不 500、不编造**；
5. **内存工程**：本机内存紧张（16GB 已用 ~12GB），故默认 `mcp` 模式复用平台已加载模型，而不是在独立进程再加载一套 BGE-M3+Reranker。
