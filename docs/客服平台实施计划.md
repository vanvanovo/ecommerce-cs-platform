## 四、意图路由实现要点（本地 Qwen 优先 + qwen-flash 回退）

**已实测（2026-10-03，本机 3060 6GB）**

| 方案 | 路由质量（样例） | 稳态延迟 | 显存占用 |
|---|---|---|---|
| qwen2:0.5b（本地） | ❌ 丢意图 / 丢槽位 | ~0.1s | 极小 |
| qwen2.5:7b 默认（82% GPU offload） | ✅ 多意图 + 槽位正确 | ~1.3s | **5.6GB（吃满）** |
| qwen2.5:7b 强制 CPU | ✅ 正确 | ~4.6s | 0（GPU 留给检索） |
| qwen-flash（云端） | 强（基线） | ~0.5~1.5s | 0 |

1. `core/llm_factory.py` 增加路由 Provider 三选一（配置切换）：
   - `ollama_cpu`：`http://localhost:11434/v1` + `num_gpu=0`，检索栈独占 GPU（**过渡默认**）
   - `ollama_gpu`：同接口，GPU 推理（检索模型需全部挪 CPU）
   - `dashscope`：`https://dashscope.aliyuncs.com/compatible-mode/v1`，qwen-flash（**超时自动回退**）
2. 服务启动时**预热路由模型**（lifespan 里预跑一次空请求，消除首次 4~8s 加载耗时）。
3. 降级链：本地 Qwen（超时 8s）→ qwen-flash → DeepSeek → 规则层 → 转人工。
4. P1 评测集 A/B（准确率 + P95 延迟）：{7b-cpu、7b-gpu、qwen2.5:1.5b（`ollama pull`）、qwen-flash}，用数据定最终默认；若 1.5b 质量够格且能在 GPU 与检索共存，最理想。
5. 输出 JSON 协议：`{"intents": [...], "slots": {...}, "need_clarify": bool, "confidence": 0~1}`
6. 成本参考：qwen-flash 输入 0.15 元/百万 token → 单次路由约 0.0002 元；仅作回退时成本可忽略。
